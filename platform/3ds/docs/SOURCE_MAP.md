# Source map — 2.0

The maintained implementation is under `platform/3ds`. `third_party/SpaghettiKart`
and its nested submodules retain their pinned APIs, source layout and notices.
The port does not rename upstream game systems to fit a new framework.

## Directories and build boundaries

| Location | Maintained responsibility |
| --- | --- |
| Root `CMakeLists.txt` | Target composition, required libraries, compile/link settings and package targets. |
| `platform/3ds/build.sh` | Torch compatibility check, dependency preparation, complete-game build and optional CIA packaging. |
| `source/` | Compiled platform implementations, game adapters and private implementation fragments. |
| `include/` | C boundaries, portable policy/math/parser types and their ownership contracts. |
| `source/art/` | Data-only generated artwork headers and the existing loading-image data unit. These are not public service interfaces. |
| `assets/` | Original port artwork, editable Python generators and private-preview drivers. |
| `cmake/` | Responsibility-specific adaptations of pinned upstream source. Output goes to the build's `generated/` tree. |
| `compat/`, `patches/` | Explicit ARM/libultra/upstream compatibility declarations and checked-in patches. |
| `update/`, `update-dependencies/` | Updater implementation, pinned dependency recipes and component licenses. |
| `romfs/`, `shaders/` | Redistributable runtime metadata/certificates and PICA shader source. |
| `tests/` | Asset-free fixtures, production-handler harnesses and optional archive/updater integration checks. |
| `docs/` | Build/use guides, configuration and compatibility references, architecture and validation. |

Generated artwork remains checked in so a normal game build needs no Pillow,
font installation, image service or ROM. Edit its producer, then regenerate and
check the output. The loading RGB565 array is an existing checked-in asset input;
it is not generated by the new HUD/map authoring tools. Probe executables are
development targets and must not be mistaken for the full game release package.

## Runtime implementation owners

Files in this table are relative to `source/`; related portable types live in
`include/`. A private `.inc.cpp`/`.inc.c` is included by its owner, not compiled
as a second translation unit.

| Subsystem | Implementation and decision |
| --- | --- |
| Application/lifecycle | `game_main_3ds.cpp`, `system_3ds.cpp`: initialization, APT, error exit and bounded final teardown. `heap_partition_3ds.cpp`, `linear_allocation_capture_3ds.cpp`, `ndsp_thread_stack_3ds.cpp`: early allocation/stack constraints. |
| First-run game data | `game_data_3ds.cpp`, `torch_o2r_3ds.cpp`, `install_log_3ds.cpp`: ROM validation, extraction/progress and install results. `loading_screen_3ds.cpp`, `art/loading_image_3ds.cpp`: loading presentation. |
| Original game adapter | `game_runtime_3ds.cpp`, `game_state_3ds.cpp`, `gbi_middleware_3ds.cpp`: engine integration, stable UI snapshots, screen/result/fade coordination and display-list bridge. |
| Game compatibility | `libultra_3ds.cpp`, `cvar_3ds.cpp`, `editor_stubs_3ds.cpp`, `vanilla_stubs_3ds.cpp`, `resource_prefetch_3ds.c`: the narrow interfaces the pinned game expects. |
| Input and game policies | `input_3ds.cpp`, `auto_mode_3ds.cpp`, `solo_modes_3ds.cpp`, `race_clock_3ds.cpp`: device mapping, AUTO pulses, solo/Battle orchestration and pause/Turbo-aware time accounting. |
| Screens and menus | `bottom_ui_3ds.cpp`: GPU texture owner, bottom composition, top overlays, state and input ordering. `options_actions_3ds.inc.cpp` and `options_view_3ds.inc.cpp`: actions versus labels/drawing. |
| Native UI art | `native_ui_3ds.inc.cpp`: resource-load preparation and three-mode variant choice. Generated arrays are in `art/`; `native_mask_3ds.hpp`, `native_sprite_3ds.hpp` and `title_credit_native_3ds.hpp` implement bounded portable decode/scale/composition. |
| Configuration | `settings_3ds.cpp`: one parser/default/preset/save owner. `file_replace_3ds.hpp`: tested recovery policy for a closed temporary settings file. |
| Rendering | `gfx_citro3d.cpp`, `gfx_window_manager_3ds.cpp`: PICA commands, render targets, presentation and native window interface. `frame_interpolation_3ds.cpp`: bounded midpoint snapshots. `fast3d_dispatch_3ds.inc.cpp`: private interpreter dispatch adaptation. |
| Scene effects | `lakitu_sprite_3ds.cpp`, `jumbotron_3ds.cpp`, `threat_warning_3ds.cpp`: copied/pinned countdown frames, race-screen capture and cached threat feedback. |
| Resources | `resource_runtime_3ds.cpp`, `o2r_archive_reader.cpp`, `resource_manager_3ds.cpp`: validated archive resources, compression, ownership/eviction and libultraship bridge. `texture_lease_3ds.hpp` protects source bytes through UI palette loads and allocation. |
| Audio | `audio_runtime_3ds.cpp`, `audio_ndsp_3ds.cpp`, `audio_dma_registry_3ds.cpp`, `audio_effects_3ds.c`: synthesis worker, NDSP queues, sample address ranges and effects adapter. |
| Diagnostics | `diagnostics_3ds.cpp`, `startup_trace_3ds.cpp`, `performance_trace_3ds.cpp`: input sampling, paused dump output and bounded telemetry. `*_probe.cpp` files exercise individual host/target contracts. |
| Results | `results_times_3ds.inc.c`, `results_time_trial_3ds.inc.c`, `results_points_3ds.inc.c`: private result presentation adapted into generated game units. |
| Updates | `update_ui_3ds.inc.cpp` and `update/`: transport/verification/install result and native menu workflow. |

The portable headers are grouped by their decision: input/SELECT/Turbo;
HUD/menu/layout; geometry/lighting/combiner/depth/alpha; archive/read-ahead/cache;
AUTO/CPU/Battle/item rules; and bounded tracing/lifecycle. They do not poll HID,
open an archive or initialize GPU resources simply by being included.

## Generated upstream adaptations

`game_core_3ds.cmake` declares the pinned game inputs. `game_engine_3ds.cmake`
assembles the generated engine and includes the relevant adaptation modules.
The renderer module handles the graphics target and interpreter integration.

| Adaptation family | Modules in `cmake/` |
| --- | --- |
| Graphics interpreter | `renderer`, `interpreter_patches`, `triangle_reuse`, `native_geometry`, `native_lighting`, `texture_owner_scan` |
| Scene/resource lifetime | `racing_resources`, `world_lifetime`, `world_tracks_bridge`, `world_effects`, `jungle_trees` |
| Game rules | `solo_modes`, `auto_mode`, `cpu_items`, `cpu_penalties`, `cpu_comic`, `item_hit_protection`, `racing_objects_items` |
| Menus/results | `menu_details`, `racing_ending`, `time_trial_hud` |
| Audio | `spatial_audio`, `racing_audio_menu` |

Names in the last table have the suffix `_3ds.cmake`. Source files generated
from them are build outputs, not the edit location. Module order matters where
one transformation prepares another's input; retain that order during a move.
After changing source enumeration, build in a fresh directory to detect omitted
files or accidentally reused objects.

## Make a bounded change

Use this map to identify the owner, then read its public header and caller.
Keep one behavior and its failure/recovery policy in one place. Explain a new
boundary through a smaller dependency or clearer lifetime, not a file-count
target. The [development guide](DEVELOPMENT.md) demonstrates a menu change;
[validation](VALIDATION.md) maps the portable checks to their evidence limits.
